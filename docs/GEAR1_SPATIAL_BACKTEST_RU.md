# Пространственный ретроспективный тест оригинального GEAR1 (2014–2015)

**Статус обновлен после получения локального отчета пользователя:** полный потоковый разбор XML завершен; контрольные SHA-256 XML и каталога соответствуют проверенному запуску и использованному нормализованному CSV. Результаты приведены в разделе 7. Тест относится к современной версии ISC-GEM v13.0 и не является строгим историческим as-of испытанием.

## 1. Что проверяет этап

`research/gear1_spatial_backtest.py` сопоставляет ячеечные ожидаемые числа событий из оригинального GEAR1 CSEP XML с реальными событиями ISC-GEM main catalogue за объявленный интервал. XML читается потоково, по одной ячейке: 6 480 000 ячеек и 200 880 000 магнитудных значений не загружаются целиком в память.

Для каждого выбранного порога Mw рассчитываются два временных окна:

1. **`full_period_hindcast`** — весь интервал XML: 2014-01-01 включительно — 2015-01-01 не включительно. Это ретроспективная оценка, а не прогноз, опубликованный до начала 2014 года.
2. **`post_issue_period`** — события строго после `issueDate=2014-06-04T23:59:59Z` до конца интервала XML. Поскольку GEAR1 — стационарная модель, ожидаемые числа в ячейках масштабируются пропорционально доле оставшегося календарного времени между `forecastStartDate` и `forecastEndDate`. Это рабочее предположение о постоянной интенсивности, а не отдельная временная модель.

В XML также указано `forecastDuration=365.25`, тогда как календарный интервал от 2014-01-01 до 2015-01-01 составляет 365 дней. Скрипт сохраняет оба значения и показывает разницу как диагностическую **при условии**, что числовое поле `forecastDuration` выражено в днях. Единицы поля этим скриптом не предполагаются, и автоматически пересчитывать XML-ячейки по этому полю он не будет. Для временного масштабирования используются точные даты начала и конца прогноза. Такой подход согласуется с описанной в pyCSEP практикой масштабировать gridded forecast по доле календарного времени/decimal years, а не по неуточненному числовому полю. См. [pyCSEP `scale_to_test_date`](https://docs.cseptesting.org/_modules/csep/core/forecasts.html).

По умолчанию используются пороги Mw ≥ 5,95; 6,45; 6,95; 7,45; 7,95; 8,45; 8,95. Дополнительно создаются карты ожидаемых чисел для Mw ≥ 5,95, 6,95 и 7,95.

## 2. Каталог и фильтры

По умолчанию выбирается только источник `ISC-GEM-main` из `global_catalogue_normalized.csv`. Это исключает случайное смешение с произвольными ComCat предпочтительными магнитудами. В расчёт входят записи, у которых:

- `mw_eligible=true`;
- Mw не ниже выбранного порога;
- известная глубина от 0 до 70 км включительно;
- время события находится внутри соответствующего окна.

Неизвестная глубина не считается мелкой, не-Mw типы не пересчитываются, supplementary catalogue автоматически не добавляется. События распределяются по той же глобальной сетке 0,1° × 0,1°; координата XML задаёт центр ячейки.

**Ограничение каталога:** ISC-GEM v13.0 опубликован в 2026 году. Его записи за 2014 год — современная ретроспективная версия каталога, а не снимок, который был доступен в 2014 году. Поэтому даже окно после `issueDate` нельзя называть полностью слепым историческим тестом без архивной версии каталога на дату выпуска.

## 3. Метрика

Для каждого порога и временного окна рассчитывается независимое пуассоновское правдоподобие по всем 6,48 млн ячеек:

\[
\log L = -\sum_i \mu_i + \sum_{i:n_i>0}\left(n_i\log\mu_i-\log(n_i!)\right),
\]

где `n_i` — наблюдавшееся число землетрясений в ячейке, а `μ_i` — ожидаемое число по GEAR1.

В качестве контрольной модели используется постоянная интенсивность на единицу площади поверхности Земли. Ей задаётся **тот же суммарный глобальный ожидаемый счёт**, что и GEAR1; поэтому сравнение в первую очередь оценивает пространственное распределение, а не даёт контрольной модели искусственное преимущество из-за иной общей частоты.

- `information_gain_nats_vs_area_uniform > 0`: пространственное распределение GEAR1 лучше равномерного по площади фона.
- Значение `< 0`: равномерный по площади фон лучше.
- `information_gain_bits_per_event`: разница правдоподобий в битах на наблюдавшееся событие.
- `observed_to_expected_ratio`: отдельная диагностика глобальной частоты. Значение выше 1 означает, что событий наблюдалось больше, чем ожидалось по GEAR1.

Пуассоновский score предполагает независимые счёты событий в ячейках. Афтершоковые последовательности и иная кластеризация не декластеризуются на этом этапе и могут влиять на score. Каждый магнитудный порог оценивается отдельно; вложенные пороги нельзя складывать как независимые наблюдения.

## 4. Запуск в PowerShell

Запускать из корня локального репозитория. Ожидается, что XML уже лежит по пути, указанному в отчёте валидации, а нормализованный каталог создан ранее через `research.global_catalog`.

```powershell
python .\research\gear1_spatial_backtest.py `
  --xml ".\data\external\gear1\run\GEAR1.global.forecast.xml" `
  --catalogue ".\research\outputs\global-catalogue\global_catalogue_normalized.csv" `
  --output ".\research\outputs\gear1-2014-spatial-backtest"
```

Если у тебя каталог лежит в другой папке, измени только значение `--catalogue`. Убедись, что это файл, созданный из ISC-GEM **main** CSV, а не ComCat-only diagnostic snapshot. При необходимости можно изменить пороги:

```powershell
--thresholds "5.95,6.95,7.95" --grid-thresholds "5.95,6.95,7.95"
```

Чтобы не создавать массивы карт, можно добавить `--no-grids`. Чтобы использовать не только ISC-GEM main, а все источники в объединённой таблице, существует `--source-filter all`, но для первого сопоставления это не рекомендуется.

## 5. Результаты

В выходной папке появятся:

- `gear1_spatial_backtest_summary.json` — контроль XML и каталога, фильтры, глобальные ожидаемые числа и итоговые scores для обоих окон и всех выбранных Mw-порогов;
- `gear1_observed_event_cells.csv` — только ячейки с наблюдавшимися событиями, их фактические счёты, ожидаемые числа GEAR1 и контрольной модели;
- `duration_audit` — сравнение продолжительности календарного интервала с сырым полем `forecastDuration`, без автоматической подгонки.
- `gear1_expected_count_Mw_ge_5p95.npy`, `...6p95.npy`, `...7p95.npy` — двумерные карты ожидаемых чисел событий за полный XML-интервал, `float32`, форма `1800 × 3600`.

В `.npy` строки идут с юга на север, столбцы — с запада на восток. Центр ячейки `[row, col]`:

- latitude = `-89.95 + row * 0.1`;
- longitude = `-179.95 + col * 0.1`.

Файлы карт содержат ожидаемые числа событий, а не вероятности. Для пуассоновской вероятности хотя бы одного события в ячейке применяется `1 - exp(-μ)`.

## 6. Что считать результатом

Сначала проверяем, что полный XML снова прочитан без пропусков/дубликатов и SHA-256 совпал с валидированным артефактом. Затем смотрим:

1. число событий и `observed_to_expected_ratio` по каждому порогу;
2. знак и величину information gain против равномерного по площади фона;
3. различия между полным hindcast и периодом после даты выпуска;
4. карты GEAR1 и таблицу ячеек, где реально произошли события.

Положительный information gain на одном годовом периоде — ещё не доказательство общей предсказательной способности. Нужны несколько независимых периодов, одинаковые правила каталога и повторяемые scores; для краткосрочных прогнозов отдельно нужны ETAS/aftershock модели.

## 7. Первый численный результат: 2014

Пользовательский отчет `gear1_spatial_backtest_summary.json` получен и проверен. Контрольные суммы входов:

- XML GEAR1: `a034c76b3a454c5f4a43df3b222569f9ebb217f56ebab5e9c7ca564d3dabdd05`;
- нормализованный каталог: `d591baed44285c15cece7150d152b68a3bd0be04b5a663e91e046dab5c7c2761`.

В XML повторно прочитаны 6 480 000 ячеек и 200 880 000 магнитудных значений. Все ячейки уникальны; отрицательных, нулевых и нечисловых значений нет. Использован источник `ISC-GEM-main`; 7 163 записей ComCat исключены source-фильтром, 291 событие исключено по глубине, 75 127 записей находятся вне годового интервала. 1 526 строк ISC-GEM main остались после этих фильтров до применения порогов Mw; для минимального прогнозного порога Mw≥5,95 в полном периоде учтено 127 событий.

|---|---:|---:|---:|

Для главного порога Mw≥5,95 наблюдалось на 9,3% больше событий, чем ожидалось. На порогах до Mw≥7,95 абсолютные различия невелики; в верхних магнитудных хвостах выборка слишком мала для сильных выводов. Нулевое наблюдение при ожидании 0,255 или 0,059 не является само по себе неожиданным для пуассоновского процесса.

Дата выпуска XML — 2014-06-04T23:59:59Z; проверка post-issue включает события строго позже этой даты до 2015-01-01. Доля времени — 0,5753425 календарного интервала.

| Mw≥5,95 | 67 | 66,855 | 1,002 |
| Mw≥6,45 | 18 | 21,702 | 0,829 |
| Mw≥6,95 | 3 | 7,003 | 0,428 |
| Mw≥7,45 | 0 | 2,194 | 0 |
| Mw≥7,95 | 0 | 0,606 | 0 |
| Mw≥8,45 | 0 | 0,147 | 0 |

На минимальном пороге суммарная интенсивность GEAR1 почти точно совпала с наблюдением во второй части периода (67 против 66,855). Для Mw≥6,95 наблюдалось меньше событий, чем ожидалось (3 против 7,003), но число событий мало; вероятность получить не более трех событий при среднем 7,003 в простой пуассоновской модели составляет около 8,2%. Не следует трактовать это как доказанный провал модели. При Mw≥7,45 и выше в post-issue периоде событий не было, но ожидание также мало.

| Порог | Полный 2014: выигрыш GEAR1 | После issueDate: выигрыш GEAR1 |

| Mw≥5,95 | +385,84 nats; 4,38 bits/event | +206,93 nats; 4,46 bits/event |
| Mw≥6,45 | +136,17 nats; 4,91 bits/event | +64,09 nats; 5,14 bits/event |
| Mw≥6,95 | +43,43 nats; 5,70 bits/event | +11,41 nats; 5,49 bits/event |

Это означает, что GEAR1 назначил фактическим эпицентрам существенно большую пространственную интенсивность, чем контрольное распределение, равномерное по площади Земли и имеющее тот же глобальный ожидаемый счет. Такой результат подтверждает, что карта не эквивалентна равномерному распределению землетрясений. **Он пока не доказывает преимущество GEAR1 над сильными сейсмологическими моделями.**

### Интерпретационные ограничения и следующий эксперимент

1. Это один календарный год и один современный ретроспективный каталог ISC-GEM v13.0 (выпуск 2026 года), а не архив того, что было известно на дату 2014 года.
2. Полный год начинается до XML issueDate. Post-issue часть начинается после даты выпуска, но использует современную версию каталога и потому также не является строгим историческим as-of blind test.
3. Величины information gain сравнивают только с равномерным по площади нулевым фоном. Сейсмичность заведомо сконцентрирована в тектонических поясах; нужен более строгий контроль с Kagan–Jackson smoothed-seismicity parent, tectonic/GSRM parent и моделью GEAR1 без одной из компонент.
4. Оригинальная публикация GEAR1 описывает оптимизацию гибридной модели по Global CMT 2005–2012, независимую ретроспективную проверку по ISC-GEM 1918–1976 и дальнейшую CSEP оценку. Новый тест 2014 года не заменяет опубликованные проверки и должен рассматриваться как дополнительная диагностика обновленного запуска.
5. Все пороги Mw≥X вложены друг в друга; строки таблицы не являются независимыми выборками. Афтершоковые/кластерные зависимости не моделируются.
6. Следующий приоритет — получить карту родительского сглаженного каталога и карту тектонической компоненты в той же сетке, выполнить одинаковый score на тех же событиях, затем провести rolling-origin оценки на нескольких временных окнах. Для формального теста CSEP также нужны симуляционные распределения consistency tests, а не один observed likelihood ratio.
