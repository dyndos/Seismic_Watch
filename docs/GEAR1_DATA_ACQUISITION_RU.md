**Проверено:** 2026-11-11

## 1. Где брать архив

Скачивать оригинальный файл `Bird_archive_for_Dryad.zip` следует со страницы Dryad по DOI выше. Не загружать архив в Git-репозиторий: он содержит сотни мегабайт исходных данных и исполняемые файлы. В репозитории хранятся эта инструкция, манифест и код проверки.

Параметры файла, проверенного для проекта 2026-11-11:

| Параметр | Значение |
|---|---:|
| Имя | `Bird_archive_for_Dryad.zip` |
| Размер | 415 643 389 bytes |
| SHA-256 | `478010791a6f9781f96bc5d3b4f20cbdb62d8ea5ea211a76b5f4cbb3f1958ccf` |
| Число файлов в ZIP | 1 465 (каталоги не считаются) |
| Размер файлов после распаковки | 941 588 849 bytes (около 0,877 GiB) |

Размер на странице Dryad указан как 415.64 MB; разница с локальным отображением в MiB объясняется единицами измерения.

SHA-256 также хранится в [research/data/Bird_archive_for_Dryad.zip.sha256](../research/data/Bird_archive_for_Dryad.zip.sha256).

## 2. Проверка в Windows PowerShell

Помести скачанный архив в рабочую папку и выполни:

```powershell
$archive = ".\Bird_archive_for_Dryad.zip"
$expected = "478010791a6f9781f96bc5d3b4f20cbdb62d8ea5ea211a76b5f4cbb3f1958ccf"
$actual = (Get-FileHash -LiteralPath $archive -Algorithm SHA256).Hash.ToLowerInvariant()

if ($actual -ne $expected) {
    throw "SHA-256 не совпадает. Архив поврежден или отличается от проверенной версии."
}

"SHA-256 OK"
```

Если контрольная сумма не совпала, не продолжай подготовку входов: сначала скачай архив заново и проверь его повторно.

## 3. Где хранить локальную копию

Рекомендуемый путь внутри локального checkout:

`data/external/gear1/Bird_archive_for_Dryad.zip`

Каталог `data/external/` исключен из Git через `.gitignore`. Распакованные исходные данные и крупные результаты также должны оставаться вне Git-истории. Не добавляй архив через `git add -f`.

Рекомендуется сохранить оригинальный ZIP неизменным. Подготовленные/переименованные файлы складывать в отдельную рабочую папку, например `data/external/gear1/run/`.

## 4. Автоматическая подготовка в Windows

В репозитории есть PowerShell-скрипт `research/prepare_gear1_windows.ps1`. Он:
- проверяет SHA-256 исходного ZIP;
- распаковывает архив и два вложенных ZIP;
- распаковывает Unix `.Z` через установленный 7-Zip;
- подготавливает шесть входов с точными именами из файла параметров;
- проверяет SHA-256 каждого входа;
- копирует оригинальный Windows x64 исполняемый файл, а для parallel-режима — соответствующую `libiomp5md.dll`;
- создает локальный `data/external/gear1/run/`, который исключен из Git.

Пример запуска из корня checkout в PowerShell:

```powershell
.\research\prepare_gear1_windows.ps1 -ArchivePath "C:\Users\<имя>\Downloads\Bird_archive_for_Dryad.zip" -ExecutionMode parallel
```

Для sequential-исполнения укажи `-ExecutionMode sequential`. Скрипт только подготавливает рабочую папку и **не запускает** многчасовой расчет. После его завершения он выведет точную команду запуска. Для распаковки `.Z` требуется установленный 7-Zip.

## 5. Что именно нужно оригинальному GEAR1

Авторская инструкция находится в архиве:

`GEAR1_forecast/how_to_build_the_GEAR1_XML_file.txt`

Файл параметров:

`GEAR1_forecast/GEAR1_parameters.dat.txt`

В параметрах перечислены шесть обязательных входов:

| Имя, ожидаемое программой | Исходное расположение в архиве | Подготовка |
|---|---|---|
| `GL_HAZTBLT_M5_B2_2013.TMP` | `GEAR1_forecast/GL_HAZTBLT_M5_B2_2013.zip` | Распаковать вложенный ZIP |
| `PB2002_tectonic_zones.grd` | `PB2002/PB2002_tectonic_zones.grd.txt` | Удалить второй суффикс `.txt` в рабочей копии |
| `underwater.grd` | `Kagan_2009_GJI_I_scores/underwater.grd.zip` | Распаковать вложенный ZIP и взять файл `underwater.grd` |
| `PB2002_steps.dat` | `PB2002/PB2002_steps.dat.txt` | Удалить второй суффикс `.txt` в рабочей копии |
| `GSRM_average_strain_v2.1.txt` | `SHIFT_GSRM2_forecast/GSRM_average_strain_v2.1.txt.Z` | Распаковать Unix `.Z` |
| `GCMT_shallow_5p767_1977-2013.eqc` | `SHIFT_GSRM2_forecast/GCMT_shallow_5p767_1977-2013.eqc.txt` | Удалить второй суффикс `.txt` в рабочей копии |

Сам файл параметров в рабочем каталоге должен называться `GEAR1_parameters.dat` (убрать второй суффикс `.txt`). Первые шесть строк параметров нельзя менять; перед запуском нужно проверить, что имена файлов в параметрах совпадают с именами входов буквально.

Для двух ZIP внутри архива можно использовать PowerShell `Expand-Archive`. Для файла `.Z` нужна поддержка Unix compress, например утилита `uncompress` в Linux. Не путай `.Z` с обычным ZIP.

## 6. Запуск и ресурсы

По авторской инструкции от 2015 года:
- требуется 64-битная Windows-система;
- в конце расчета используется около 3,8 GB RAM, автор рекомендует иметь 5–6 GB общей оперативной памяти;
- sequential-версия может работать около двух суток;
- parallel-версия — ориентировочно 3–12 часов и требует соответствующую Intel OpenMP DLL;
- результат — CSEP XML примерно 3,8 GB.

Это требования и оценки автора для его исходной версии, а не подтвержденные характеристики запуска в нашей среде. Перед полным расчетом нужно проверить контрольные суммы шести подготовленных входов, параметры, свободное место и логирование.

### Альтернативная сборка GNU Fortran в Linux

В репозитории добавлен сценарий `research/build_gear1_gfortran.sh`. Он берет неизмененные исходники из `data/external/gear1/source/`, создает совместимые рабочие копии и собирает ELF-бинарный файл:

```bash
bash research/build_gear1_gfortran.sh full
```

Для диагностической сборки, которая останавливается после этапа 2 и не создает XML:

```bash
bash research/build_gear1_gfortran.sh diagnostic-step2
```

Для компиляции нужны GNU Fortran и Python 3. Полные и диагностические бинарные файлы создаются в `data/external/gear1/build_gfortran/`.

**Ограничение:** эта сборка заменяет Intel MKL VSL на GNU Fortran intrinsic RNG. Поэтому она не воспроизводит авторскую последовательность MCG31 и не считается побитово идентичной оригинальному Windows EXE. Для основной репликации предпочтителен авторский Windows-бинарник. GNU-сборка пригодна для технической диагностики и проверки чувствительности к RNG, но требует отдельного сравнения результатов.

**Не запускать полный расчет в папке Git-репозитория с включенным отслеживанием выходных файлов.** XML и промежуточные результаты должны оставаться в локальном исключенном каталоге.

## 7. Лицензия и осторожность при повторном использовании

Страница Dryad публикует набор как исследовательский dataset; руководство Dryad указывает, что наборы данных репозитория распространяются под CC0. При этом распакованный файл `GSRM_average_strain_v2.1.txt` содержит собственное уведомление GEM о CC BY-NC-SA 3.0 (unported).

Это расхождение нельзя игнорировать или разрешать предположением. Для проекта сохраняем исходное уведомление GEM и консервативно считаем условия использования именно этого компонента требующими отдельного уточнения у правообладателя/поставщика. До выяснения не распространяем этот файл отдельно и не заявляем, что его коммерческое использование разрешено. Ссылка на Dryad и DOI сохраняются для происхождения данных.
